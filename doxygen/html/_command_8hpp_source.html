21/**
22 * A state machine representing a complete action to be performed by the robot.
23 * Commands are run by the CommandScheduler, and can be composed into
24 * CommandGroups to allow users to build complicated multi-step actions without
25 * the need to roll the state machine logic themselves.
26 *
27 * <p>Commands are run synchronously from the main robot loop; no
28 * multithreading is used, unless specified explicitly from the command
29 * implementation.
30 *
31 * <p>Note: ALWAYS create a subclass by extending CommandHelper<Base, Subclass>,
32 * or decorators will not function!
33 *
34 * This class is provided by the Commands v2 VendorDep
35 *
36 * @see CommandScheduler
37 * @see CommandHelper
38 */
39class Command : public wpi::telemetry::TelemetryLoggable,
40 public wpi::tunables::ComplexTunable {

83 * <p>Note: it is recommended that user implementations contain the

92 /**

94 *

96 * from being scheduled simultaneously.

98 * Note that the scheduler determines the requirements of a command when it
99 * is scheduled, so this method should normally be called from the command's

101 *
102 * While this overload can be used with {@code AddRequirements({&subsystem1,

104 * AddRequirements(Subsystem*)} overload, which will function identically but
105 * may cause warnings about redundant braces.

154 /**
155 * An enum describing the command's behavior when another command with a
156 * shared requirement is scheduled.
157 */
158 enum class InterruptionBehavior {
159 /**
160 * This command ends, End(true) is called, and the incoming command is
161 * scheduled normally.
162 *
163 * <p>This is the default behavior.
164 */
165 CANCEL_SELF,
166 /** This command continues, and the incoming command is not scheduled. */
167 CANCEL_INCOMING
