140 /**
141 * Runs a callback after the current update cycle finishes resetting changed
142 * flags.
143 *
144 * Backends should use this for callbacks that react to tuned values so

146 *
147 * @param callback callback to run; must not throw

151 /**
152 * Get the mutex used during Update() execution.
153 *
154 * As tunables are not thread-safe, this is designed to allow external
155 * synchronization for tunables used in secondary threads outside of the robot
156 * main loop.
157 *
158 * Every competing access, including main-loop access, must use this mutex or
159 * another safe handoff. The mutex is held while backends and user callbacks
160 * run, so critical sections should be short. References returned by a
161 * tunable must not be used after releasing the mutex if another thread can
162 * access the value.
163 *
164 * Note the returned mutex is recursive, so registry operations invoked from
165 * an update callback on the same thread can re-enter it. It still does not
166 * make tunable objects themselves thread-safe.
167 *
168 * @return mutex
169 */
170 static wpi::util::recursive_mutex& GetUpdateMutex();
171
172 /**
173 * Clear all registered backends. Should typically only be used by unit test
